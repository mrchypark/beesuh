# Rhiza v0.27.3 consumer assessment

Baseline: Beesuh main `5fc58f92e059ca1ad71c2ccc334518811c35bc49`, with Rhiza v0.23.3 and LatticeDB Go v0.11.3.

The artifact gate confirmed [Rhiza v0.27.3](https://github.com/mrchypark/rhiza/releases/tag/v0.27.3) at `234602aeb1783f11f1e878a5e1a4793ff7a473d6`, the published [Rhiza](https://sum.golang.org/lookup/github.com/mrchypark/rhiza@v0.27.3) and [LatticeDB Go v0.13.0](https://sum.golang.org/lookup/github.com/mrchypark/latticedb-go@v0.13.0) module checksums, the embedded SQLite Wasm artifact, and the unchanged Go 1.27.4 linux/amd64 Docker builder. The [Rhiza module manifest](https://proxy.golang.org/github.com/mrchypark/rhiza/@v/v0.27.3.mod) keeps the Go floor at 1.27.4 and LatticeDB Go at v0.13.0.

The intervening releases add managed HA membership and NoPVC operator work, indexed graph reads, and hardening in embedded SQL materialization, rollback failure, recovery, transport, and SQL receipt paths. Beesuh uses the public root SDK for a local single voter with no archive or operator configuration. The consumed API surface compiles without source changes, and the repository suite covers migrations, transactional execution, cancellation, and local reopen behavior. Managed HA, operator image upgrades, remote archive recovery, and NoPVC deployment behavior remain outside this consumer path.

Hosted CI builds the seed helper from the current source against the fixed v0.23.3 module manifests. After the seed commits its run, history, and session records, the test kills it with SIGKILL and opens the same disposable DataDir using the v0.27.3 module graph. It checks that replay makes no extra model call and that a new run uses the recovered history. This is a module-graph compatibility check for a source-neutral dependency update; it does not execute the historical v0.23.3 source tree. The v0.22.0 Query cancellation negative control retains the baseline's other pins and still requires loss of the context cause in both modes. Candidate acceptance requires passing CI at the exact candidate commit. This fixture does not qualify cross-version connection, cancellation, or recovery-fence records, downgrade, or recovery after volume loss.

The managed HA membership and NoPVC operator changes do not apply to Beesuh's embedded single voter. Both init and main open local storage with no object archive, and the Kubernetes example retains its PVC. [Rhiza's single-node archive recovery](https://github.com/mrchypark/rhiza/blob/v0.27.3/docs/local-init-container-recovery.md) requires Local mode, a configured archive, matching init and main storage settings, and external exclusion of the old writer. Beesuh does not provide PVC-less object recovery with its current wiring.
